# 測試案例：狀態寫入（HOOK）

> 由 dev-test-plan 於 2026-10-09 產出。經使用者 review 確認後，才據此撰寫測試程式。
> 業務邏輯計算的「期待輸出」必須由使用者親自驗算，勾選「使用者已驗算」欄才算定案。
> 期待值取自已核准的 `docs/specs/SPEC.md` v1（HOOK 模組）。

## 涉及檔案

- 被測：`scripts/pet-state.sh`（以 Git Bash 實際執行，stdin 餵模擬的 hook 資料）、`hooks/hooks.json`、`install.py`（事件對應表）
- 測試程式：`tests/test_pet_state.py`
- 測試資料：執行時 HOME 指向暫存資料夾，不碰真正的 `~/.terminalpet/`

> 限制：通知類型的實際過濾由 Claude Code 執行，本測試只驗設定內容（T13）。找不到 Git Bash 的環境略過 T01～T12、T14。
> 每次執行腳本都要以結束碼 0 離開（全域規則：不拖累 Claude Code），每條案例都會一併檢查。

> 「規格條文」——這條案例守的是哪個 AC；測試程式的名稱也帶這個編號，驗收時才對得回去
> 「使用者已驗算」——計算類案例必填 ✅；非計算類填 ⊘ 不適用
